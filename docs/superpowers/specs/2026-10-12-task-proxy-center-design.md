# ARTEX 任务代理中心设计

## 目标

为 ARTEX 增加统一代理中心，支持普通 HTTP/HTTPS/SOCKS5、轻量 WARP 和已运行的 Resin 动态代理，并让全局默认代理与任务级代理选择同时覆盖任务工具流量和任务使用的 LLM API 流量。

## 范围

- 代理中心用稳定的数据库编号展示代理记录。
- 代理记录包含类型、连接地址、协议、启用状态、检测状态和脱敏凭据。
- WARP 使用本地 `wgcf + wireproxy` 出口；ARTEX 只管理本地出口生命周期，不改变宿主机默认路由。
- Resin 作为外部服务接入。ARTEX 保存数据面连接参数及控制面配置，使用 Platform 与任务稳定 Account 键管理粘性出口；不部署 Resin 服务。
- 全局默认代理保存代理编号，替代旧的单 URL `global_proxy`，同时保留旧配置迁移能力。
- 任务代理模式为 `inherit`、`direct`、`fixed`，创建任务时保存模式和代理编号；任务启动时解析并固定有效代理快照。
- 任务代理覆盖 Bash、WebFetch、浏览器、HTTP 自定义工具和任务 LLM Transport。
- 指定代理失效时拒绝任务网络请求，禁止静默回退直连。
- 被运行任务引用的代理不能停用或删除。

## 明确不在本期范围

- 不把 Resin 部署到 ARTEX 或目标服务器。
- 不改变系统更新、管理后台、Cloudflare 等平台自身出站请求的代理行为。
- 不保证原始 TCP、DNS 或忽略 HTTP/SOCKS 环境的工具走任务代理；这些能力必须在任务能力说明中标记边界。
- 不把浏览器 MCP 的全局共享代理配置继续作为任务代理实现；浏览器运行时使用任务专用出口配置。

## 数据与解析语义

代理类型统一使用 `kind`：`http`、`https`、`socks5`、`warp`、`resin`。Resin 数据面使用 `host`、`port`、`protocol`、`password`；控制面使用 `resin_platform`、`resin_admin_url`、`resin_admin_token`。用户名由运行时按 `artex_task_<taskID>` 生成，不能让用户覆盖粘性账号键。

任务选择优先级为：任务明确直连、任务固定代理、LLM Profile 明确代理、全局默认代理、直连。任务固定代理一旦解析成功即生成快照，后续全局设置变化不影响该任务。

Resin 连接前执行 `healthz`、Bearer 管理认证和 Platform 查询；Lease 释放采用幂等 DELETE；不明确的创建或释放结果保留记录和材料，禁止自动重复注册或静默放宽出口。

## 并发与安全

现有流量录制 MITM 只有一个共享上游，不能通过运行时切换全局上游来实现任务代理。任务必须持有独立的出口上下文；捕获流量按任务身份选择上游，捕获关闭时直接把任务出口注入相关工具。代理凭据写入数据库时加密或使用受控密钥引用，API 和前端只返回脱敏值。

停用、删除或更新代理前检查活动任务引用。代理故障时任务进入明确失败状态，并记录代理编号、类型和诊断，不显示 Token、密码或完整带认证 URL。

## 验收标准

1. 创建普通代理、WARP 和 Resin 记录后都能在同一代理列表显示稳定编号。
2. 全局默认可选择代理编号；旧 `global_proxy` 能迁移为普通代理记录。
3. 任务创建表单支持继承全局、指定编号和明确直连，任务详情显示实际代理快照。
4. 两个并发任务选择不同代理时，请求出口不会串线。
5. 任务 LLM 请求与任务工具请求使用同一解析后的代理；LLM Profile 明确代理仍遵循优先级规则。
6. 代理失效、停用或被删除时，任务拒绝网络请求且不回退直连。
7. Resin 健康检查、Platform 选择、任务 Account 粘性键和 Lease 释放均有后端测试。
8. 旧任务、旧设置、无代理直连和现有独立 WebSearch 配置保持兼容。
